# 🔒 Security Policy

## Supported Versions

We actively provide security fixes and maintenance updates for the following versions:

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

The Pulse Music development team takes software security and user privacy seriously. If you discover a potential vulnerability in Pulse Music, please follow the responsible disclosure guidelines below.

### Disclosure Process
1. **Do not publicly disclose** the issue on public forums, GitHub Issues, or social media.
2. Email your discovery and details to `security@example.com` or create a confidential security advisory on GitHub.
3. Include the following details in your report:
   - Type of vulnerability (e.g., buffer overflow, insecure storage, URI injection).
   - Component or file affected (e.g., `TrackDownloadManager`, `MusicPlaybackService`).
   - Step-by-step instructions or proof-of-concept (PoC) to reproduce the issue.
   - Any potential impact on users or devices.

### Response Timeline
- We will acknowledge receipt of your vulnerability report within **48 hours**.
- We will provide an assessment and timeline for a patch within **7 business days**.
- Once a fix is verified and released in an updated version, you will be credited in the release notes (unless you request anonymity).

Thank you for helping keep Pulse Music secure!
